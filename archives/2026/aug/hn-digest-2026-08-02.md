## 5. [Sharing an X11 Server Across Hosts with FamilyWild](https://news.ycombinator.com/item?id=49147978) (↑23, 💬5)
**Article:** The article explains that X11 .Xauthority cookie rejection across containers or SSH occurs because each cookie is keyed by hostname, so the client fails to match its own hostname to the cookie entry. The fix is a one-line sed command that rewrites the cookie's family field from FamilyLocal to FamilyWild (0xffff), making it match any hostname while still requiring the secret. The author recommends this instead of xhost +, which disables authorization entirely and lets any client access keystrokes, windows, and input injection.

**Comments:** Commenters question whether xhost + is really dangerous since modern Xorg typically doesn't listen on TCP by default and socket permissions can limit access. One suggests the narrower `xhost +si:localuser:jack` as a useful alternative, while another notes the FamilyWild approach still relies on keeping the cookie file secret. Others share nostalgic memories of using X11 across networks in the 1990s and mention xrdp as a simpler modern solution.
